# Civi

Веб-игра в жанре «Цивилизация». Разрабатывается поэтапно; сейчас идёт
этап 1 — проектирование двух параллельных деревьев развития
(технологии за Науку и социальные концепции за Культуру).

## Структура репозитория

```
docs/                    проектные документы и интерактивный прототип доски
  … Проектирование дерева технологий.md      решения, списки, открытые вопросы
  … Прототип дерева технологий (интерактив).html
                         самодостаточная страница: обе доски, генерация
                         раскладки, ручная правка, сохранение в localStorage

db/                      база данных
  README.md              описание схемы и готовые запросы
  catalog/               ИСТОЧНИК ПРАВДЫ по содержанию деревьев
    eras.txt             эпохи и их исторические рамки
    categories.txt       категории технологий и их цвета
    trees.json           технологии с описанием и справкой, авторские связи
                         и готовая раскладка базовой пары деревьев
  schema/0001_schema.sql схема, правится руками
  migrations/            готовые миграции (собираются из schema/ + catalog/)
  tests/                 сквозной сценарий и проверки ограничений

app/                     модуль админки (PHP 7.4, без зависимостей)
  Rng.php                детерминированный ГПСЧ: одно семя — одна раскладка
  TreeGenerator.php      правило сквозных столбцов и барицентры, порт с прототипа
  VersionRepository.php  генерация, сохранение, загрузка и проверка версий
  Catalog.php            категории, технологии, эффекты
  Db.php, Auth.php       подключение к базе и вход по паролю
  views/                 шаблоны страниц

public/                  корень сайта
  index.php              единственная точка входа, маршрут в параметре p
  assets/                стили и отрисовка доски
  uploads/tech/          картинки технологий

config/config.php.example  образец конфигурации (доступ к базе, хеш пароля)

tools/                   вспомогательные скрипты
  generate-migration.js  собирает миграцию 0001 из схемы и каталога
  run-db-tests.sh        прогон миграции и тестов на живой базе
  validate-catalog.js    проверка каталога: ссылки, раскладка, правило столбцов
  make-stone-icons.js    векторные иконки технологий каменного века
  audit-tree-layout.js   проверка правил раскладки в прототипе
  make-password-hash.php хеш пароля для админки
```

## Админка

Развёртывание на веб-сервере — [`INSTALL.md`](INSTALL.md). Коротко:

```bash
mysql -u civi -p civi < db/migrations/0001_create_tech_tree_versions.sql
cp config/config.php.example config/config.php
php tools/make-password-hash.php     # хеш вставить в config.php
```

Корень сайта — каталог `public/`. Что умеет:

- генерировать версию пары деревьев по семени и сохранять её в базу;
- находить сохранённые версии по коду семени или по названию и открывать доску;
- добавлять в версию технологии вручную, в том числе вне стандартного набора,
  и убирать карточки с доски;
- вести каталог: категории с цветами, технологии с картинкой, описанием
  и исторической справкой, зависимости;
- описывать, что технология добавляет в игру (ресурс, юнит, здание и его
  уровень, концепция, карточка, ускорение добычи), список видов пополняется
  через интерфейс без миграций;
- править связи прямо на доске: кнопки «‹» и «›» по бокам карточки включают
  выбор основ и последователей, карточка сразу встаёт в столбец за самой
  поздней из своих основ, и правка сохраняется;
- считать стоимости: над каждым столбцом — среднее, кнопка пересчёта столбца
  и его сумма, над эпохой — пересчёт всей эпохи и её итог, над доской —
  закреплённая панель с обоими коэффициентами, кнопкой пересчёта всех эпох
  и общим итогом версии;
- смотреть карточку не выходя из дерева: кнопка «i» открывает окно
  с описанием, исторической справкой и соседями по связям (со стоимостью
  в скобках) — по соседям можно ходить, окно не закрывается;
- деревья переключаются вкладками, доска таскается мышью за фон
  в обе стороны.

## Содержимое деревьев

Каталог в `db/catalog/` — источник правды: 15 эпох, 41 категория,
623 технологии (327 научных и 296 культурных), у каждой описание для игрока
и историческая справка, между ними 1237 авторских связей. Там же лежит
готовая раскладка обеих досок по столбцам — миграция кладёт её в базу
версией №1 «Базовые деревья», поэтому сразу после наката админка открывает
пару деревьев как есть.

Стоимость технологии определяется её столбцом. Средняя стоимость первого
столбца — 60, дальше работают два коэффициента: следующий столбец **внутри
эпохи** дороже предыдущего в 1.1 раза, а первый столбец **новой эпохи** —
в 1.5 раза. Внутри эпохи цена растёт полого, на смене эпохи делает заметный
шаг. Все три числа хранятся у версии и правятся прямо на доске:
коэффициенты — в закреплённой панели над деревьями, среднее — над каждым
столбцом. Разброс внутри столбца считается от меньшего из коэффициентов
так, чтобы диапазоны соседних столбцов не пересекались.

Проверить источники каталога:

```bash
node tools/validate-catalog.js
```

Ручная правка связей может выстроить внутри эпохи цепочку длиннее, чем
столбцов в этой эпохе. Тогда эпоха получает дополнительный столбец (сквозная
нумерация следующих эпох едет вправо), а лишние пустые столбцы в конце эпохи
убираются обратно, но меньше двух не становится. Стоимости самих технологий
при этом не трогаются — меняются только средние по столбцам, которые считаются
от первого столбца; пересчитать стоимости можно кнопками над столбцом, эпохой
или над всей доской.

## Прототип доски

`docs/… (интерактив).html` открывается файлом, без сервера. Это макет первого
этапа: он хранит правки в localStorage и содержит **старый состав технологий**
до перегруппировки. Актуальный каталог живёт в `db/catalog/` и в базе, работать
с ним нужно через админку — прототип оставлен как история решения.

Правила раскладки, которые прототип соблюдает:

- эпохи идут слева направо, внутри каждой 2 или 3 столбца; третий
  добавляется случайно;
- технологии одной категории внутри эпохи расходятся по разным столбцам
  слева направо, поэтому внутри ветки хронология не путается;
- стоимость растёт от столбца к столбцу в заданное число раз (внутри эпохи
  и на её границе — по-разному), внутри столбца расходится случайно,
  и диапазоны соседних столбцов не пересекаются;
- столбцы нумеруются сквозной нумерацией через все эпохи;
- технология без зависимостей возможна только в первом столбце первой эпохи;
- любая другая опирается минимум на одну технологию из непосредственно
  предыдущего столбца, то есть встаёт сразу за столбцом, где лежит самая
  поздняя из её основ; дополнительные связи уходят в любые более ранние
  столбцы;
- для первого столбца новой эпохи правило смягчено: чаще всего связь идёт
  в последний столбец предыдущей эпохи, иногда — глубже в прошлое;
- порядок карточек внутри столбца считается методом барицентров, карточки
  распределяются по всей высоте столбца.

Проверить, что правила соблюдены:

```bash
npm i playwright-core
node tools/audit-tree-layout.js
```

## База данных

Схема, стандартный набор данных и запросы описаны в [`db/README.md`](db/README.md).

```bash
mysql -u root -p civi < db/migrations/0001_create_tech_tree_versions.sql
```

Пересобрать миграцию после правки схемы или данных прототипа:

```bash
node tools/generate-migration.js
```

Прогнать миграцию и тесты на живой базе:

```bash
MYSQL_ARGS="-h 127.0.0.1 -u root -proot" tools/run-db-tests.sh
```
